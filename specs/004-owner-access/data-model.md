# Data Model: Owner Access and Invitations

All timestamps are UTC `timestamptz`. IDs are UUIDs generated by application code. Email
and display values are bounded before persistence. Secrets never appear in table names,
comments, audit payloads, event payloads, or delivery-status detail.

## User

One stable person identity.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Primary key |
| `email` | text | Current delivery/display form, max 320 characters |
| `normalized_email` | text | Unique deterministic comparison key, max 320 |
| `display_name` | text | Trimmed, 1–120 characters |
| `role` | text | `owner` or `member` |
| `status` | text | `active` or `deactivated` |
| `email_verified_at` | timestamptz | Required for active users |
| `created_at` | timestamptz | Immutable |
| `updated_at` | timestamptz | Changes with account metadata/status |
| `deactivated_at` | timestamptz nullable | Required only when deactivated |

Constraints and indexes:

- Unique `normalized_email`.
- Unique partial index permitting at most one row whose role is `owner`; owner lifecycle
  operations cannot deactivate/demote/delete it in this feature.
- Member rows have no relationship to `owner_credentials`.
- Status/timestamp consistency checks.

State transitions:

```text
invited (Invitation only) → active member ⇄ deactivated member
no owner → active owner (once; bootstrap permanently closes)
```

Deactivation revokes sessions and outstanding login challenges in the same transaction.
Reactivation does not create a session, password, or code.

## Bootstrap State and Capability

`bootstrap_state` is a singleton row that closes setup independently of capability
cleanup. `auth_capabilities` stores high-entropy setup and owner-recovery capabilities.

### Bootstrap state

| Field | Type | Rules |
|---|---|---|
| `singleton` | boolean | Primary key, always true |
| `closed_at` | timestamptz nullable | Non-null permanently after owner creation |
| `owner_user_id` | uuid nullable | Unique FK to the created owner; same nullability as `closed_at` |

### Auth capability

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Primary key |
| `kind` | text | `owner_setup` or `owner_recovery` |
| `user_id` | uuid nullable | Null for setup; owner FK for recovery |
| `token_digest` | bytea | Unique 32-byte purpose-separated keyed digest |
| `expires_at` | timestamptz | Setup 15 minutes; recovery 30 minutes |
| `consumed_at` | timestamptz nullable | One-use marker |
| `revoked_at` | timestamptz nullable | Explicit/superseded marker |
| `created_at` | timestamptz | Immutable |

Only one usable capability of a kind/user remains after issuance. Consumption uses a
conditional update inside the owner creation/recovery transaction. Cleanup may retain
expired/consumed metadata for audit but never token plaintext.

## Owner Credential

Exactly one credential row, owned by the owner.

| Field | Type | Rules |
|---|---|---|
| `user_id` | uuid | Primary key/FK to owner |
| `password_hash` | text | Self-describing Argon2id encoding, max 512 |
| `changed_at` | timestamptz | Used for session/security reporting |
| `created_at` | timestamptz | Immutable |

Application invariants verify the user role is owner. Password plaintext exists only for
request processing and is never logged. A successful recovery updates this row, consumes
the capability, revokes all recovery capabilities and owner sessions, and records audit/
event effects atomically.

## Invitation

Owner authority for one member activation.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Primary key |
| `email` | text | Intended delivery form |
| `normalized_email` | text | Indexed intended identity |
| `token_digest` | bytea | Unique 32-byte purpose-separated keyed digest |
| `state` | text | `pending`, `accepted`, `revoked`, or `expired` |
| `expires_at` | timestamptz | Seven days after latest issuance |
| `accepted_by_user_id` | uuid nullable | FK to the activated member |
| `accepted_at` | timestamptz nullable | Paired with accepted user |
| `revoked_at` | timestamptz nullable | Paired with revoked state |
| `created_by_user_id` | uuid | FK to the owner |
| `created_at` | timestamptz | Immutable |
| `updated_at` | timestamptz | Resend/state update |
| `resend_count` | integer | Nonnegative, bounded by service policy |

Only one pending invitation may exist per normalized email. Resend revokes the old token
digest, sets a new expiry/digest on the same invitation lineage, increments the count,
and creates a new delivery record. Acceptance locks the invitation, checks current time,
email/account conflicts and bootstrap owner identity, creates or reactivates exactly one
member as permitted, consumes the invite, and may create the initial session atomically.

## Member Login Challenge

One issued six-digit member-code attempt set.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Primary key |
| `user_id` | uuid | FK to active member |
| `code_digest` | bytea | 32-byte purpose-separated HMAC digest |
| `state` | text | `active`, `used`, `superseded`, `expired`, or `revoked` |
| `expires_at` | timestamptz | Exactly ten minutes after issue |
| `used_at` | timestamptz nullable | Paired with used state |
| `invalidated_at` | timestamptz nullable | Superseded/revoked time |
| `created_at` | timestamptz | Issue time |
| `delivery_id` | uuid nullable | FK to safe delivery lifecycle |

A partial unique index allows at most one active challenge per member. Issuance locks the
member login state, invalidates an earlier active challenge, inserts the new row, and
updates delivery counters atomically. Correct verification conditionally consumes the
active row. Leading-zero code text is never converted to an unpadded stored integer.

## Member Login State and Failure Event

Durable member-specific controls plus the rolling history used for the tenth-attempt
threshold.

### Member login state

| Field | Type | Rules |
|---|---|---|
| `user_id` | uuid | Primary key/FK to member |
| `consecutive_failures` | smallint | 0–3; reset by successful login or owner unlock |
| `blocked_until` | timestamptz nullable | 15-minute temporary block |
| `administratively_locked_at` | timestamptz nullable | Only owner unlock clears |
| `locked_reason` | text nullable | `wrong_code_limit` only in this feature |
| `last_code_sent_at` | timestamptz nullable | One-minute delivery bound |
| `updated_at` | timestamptz | Durable state version |

### Login failure event

| Field | Type | Rules |
|---|---|---|
| `id` | bigint | Monotonic primary key |
| `user_id` | uuid | FK to member |
| `challenge_id` | uuid | FK to challenge |
| `occurred_at` | timestamptz | Rolling-window timestamp |
| `origin_digest` | bytea | Keyed network-origin digest, not raw address |

Verification serializes on the login-state row. An eligible wrong code inserts one
failure event, increments consecutive failures, and counts events newer than `now-24h`.
At count 3 it sets `blocked_until=now+15m`; at count 10 it sets the administrative lock
and revokes active challenges. Submissions while blocked/locked or without an eligible
active challenge do not create additional member failure events. Owner unlock clears
state, deletes/archives rolling failure events according to retention, and revokes codes
in one audited transaction.

## Authentication Rate Event

Durable sliding-window input for delivery and origin controls.

| Field | Type | Rules |
|---|---|---|
| `id` | bigint | Monotonic primary key |
| `bucket_kind` | text | `member_code_delivery`, `origin_code_request`, `origin_code_verify`, `owner_login`, or `owner_recovery` |
| `bucket_digest` | bytea | Purpose-keyed digest of normalized email/user/origin |
| `occurred_at` | timestamptz | Indexed with bucket |

Rows contain no raw email or network address. Expired rate rows are pruned by bounded
in-process maintenance. Rate decisions and relevant insertions occur in one transaction
or under a PostgreSQL advisory lock for the bucket to prevent concurrent limit bypass.

## Session

Opaque authenticated browser/device session.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Public safe identifier for session management |
| `user_id` | uuid | FK to user |
| `token_digest` | bytea | Unique 32-byte keyed digest; token only in cookie |
| `csrf_digest` | bytea | Separate keyed digest of CSRF token |
| `created_at` | timestamptz | Immutable |
| `last_seen_at` | timestamptz | Server-updated with bounded write frequency |
| `idle_expires_at` | timestamptz | At most eight hours after activity |
| `absolute_expires_at` | timestamptz | 30 days after creation |
| `revoked_at` | timestamptz nullable | Server-side invalidation |
| `revoked_reason` | text nullable | Safe enum |
| `device_label` | text | User-agent-derived, bounded and non-authoritative |
| `origin_digest` | bytea | Keyed coarse origin metadata, not displayed raw |

A request is authenticated only when the digest matches, both expiries are future, the
session is unrevoked, and the user is active. Session lists never return token or digest.
The current session is marked by comparison in the service result.

## Account Email Delivery

Safe lifecycle metadata for transactional account mail.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Primary key |
| `kind` | text | `invitation`, `member_login_code`, `owner_recovery`, or `security_notice` |
| `recipient_email` | text | Required for actual delivery; owner-visible only where authorized |
| `subject_user_id` | uuid nullable | User concerned by the message |
| `invitation_id` | uuid nullable | Optional related invite |
| `challenge_id` | uuid nullable | Optional related challenge |
| `state` | text | `pending`, `sending`, `sent`, `failed`, or `abandoned` |
| `attempt_count` | smallint | Bounded nonnegative count |
| `last_attempt_at` | timestamptz nullable | Safe timing |
| `sent_at` | timestamptz nullable | Successful handoff |
| `error_code` | text nullable | Sanitized category, never raw provider response |
| `created_at` | timestamptz | Immutable |

The row never stores plaintext capability URLs or login codes. If the process loses the
in-memory secret before provider handoff, the pending delivery becomes `abandoned` and a
fresh resend/issue creates a new secret and row.

## Security Audit Event

Immutable, append-only security evidence.

| Field | Type | Rules |
|---|---|---|
| `id` | bigint | Monotonic primary key |
| `occurred_at` | timestamptz | Immutable |
| `event_type` | text | Reviewed bounded vocabulary |
| `actor_user_id` | uuid nullable | Authenticated actor when present |
| `subject_user_id` | uuid nullable | Account affected |
| `session_id` | uuid nullable | Safe session identifier |
| `outcome` | text | `succeeded`, `failed`, `blocked`, or `locked` |
| `origin_digest` | bytea nullable | Keyed, never raw origin |
| `metadata` | jsonb | Schema-validated safe fields only |

Database privileges/application APIs do not expose update/delete operations. Metadata
must not contain emails unless an owner administration view explicitly requires the
normalized target, and never contains passwords, tokens, codes, digests, private
financial content, raw headers, or provider error text.

## Client Event Authorization Extension

The feature-002 `client_events` row gains:

| Field | Type | Rules |
|---|---|---|
| `scope` | text | `shared`, `user`, or `owner` |
| `subject_user_id` | uuid nullable | Required only for `user`; forbidden otherwise |
| `event_type` | text | Versioned name such as `session.revoked.v1` |
| `entity_type` | text | Safe read-model name |
| `entity_id` | uuid nullable | Safe affected identifier |
| `payload` | jsonb | Minimal invalidation metadata, never secret material |

Scope constraint:

```text
shared → subject_user_id is null
owner  → subject_user_id is null; current owner role required
user   → subject_user_id is non-null and equals authenticated user
```

Account events include setup state, invitation delivery/state, member status/lock state,
and safe session lifecycle. A member's private financial events never become owner scope.

## Transaction Boundaries

- Bootstrap: capability consume + owner/user credential + close state + session + audit
  + user/owner events.
- Recovery: capability consume + credential update + all-session/capability revoke +
  audit + owner event.
- Invitation acceptance: invite consume + member activation + login state + optional
  session + audit + owner/user events.
- Wrong code: challenge/login-state lock + failure event + possible block/lock + audit +
  owner/user event when visible state changes.
- Unlock/deactivate/session revoke: authorization check + state mutation + dependent
  token/session revocations + audit + appropriately scoped events.

No client-visible mutation commits without its durable event. No security transition
commits without its safe audit row.
